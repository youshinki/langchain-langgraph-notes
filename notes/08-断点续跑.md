# 第08篇：断点续跑续在哪｜LangGraph系列

欢迎来到《把 Agent 画成图：18 篇吃透 LangChain 与 LangGraph》，这是第 08 篇。从 LangChain 1.x 的 `create_agent` 讲到 LangGraph 运行时，再到工程化落地。

上一篇讲完分叉，这一篇讲"断了怎么办"。LangGraph 的续跑不是靠日志重放，也不是靠你自己存快照，而是靠 checkpointer 在每个 super-step 边界存下的一份状态快照。搞清它存在哪、什么时候存、续跑从哪开始，才敢把 agent 放到线上。

## 一、checkpoint 存在 super-step 边界

给图挂上 checkpointer，每次执行都会在 super-step 边界存一个 `StateSnapshot`。一个 `START -> A -> B -> END` 的串行图，跑一遍会留下四个 checkpoint：空状态、用户输入、A 的输出、B 的输出。

注意 A 和 B 是两个不同的 super-step，所以各存一次。并行分支因为属于同一个 super-step，只会在这一步结束后存一次——这也是上一篇强调"同一份旧状态"的延续。

一份快照里主要装四样：`values`（各 channel 的值）、`next`（下一步该跑哪些节点）、`metadata`（来源、谁写了什么、第几步）、`parent_config`（上一份是谁）。所以"续在哪"这个问题，答案其实就写在 `next` 里：它列着还没跑的节点名。

编译时挂上就行：

```python
from langgraph.checkpoint.memory import InMemorySaver

graph = builder.compile(checkpointer=InMemorySaver())
```

## 二、thread 是主键，没它就没有续跑

checkpointer 用 `thread_id` 存取。调用时必须带：

```python
config = {"configurable": {"thread_id": "order-1001"}}
graph.invoke({"messages": [{"role": "user", "content": "查一下订单"}]}, config)
```

同一个 `thread_id`，第二次调用会接着上次的状态；换一个 `thread_id`，就是全新的一根线。这不是"会话 ID"那种可有可无的装饰，而是主键：没有它，HITL、续跑、回溯统统不存在。

工程上我一般把 `thread_id` 设计成 `业务实体:子场景`，比如 `order-1001:refund`。用户重开一次对话但聊同一件事，ID 不变，记忆就在；想重置，换后缀即可。这样排查线上问题时，拿业务单号就能直接翻出这根线。

还有个容易误会的点：往已有 thread 传新输入，**不会清空历史**。输入会按 reducer 合进旧状态，消息列表就是这么越堆越长的。想要干净开局，只能换 `thread_id`。

## 三、四种调用，对应四种意图

文档给了一张很实用的表，我把它当口诀用：

| 想干什么 | 怎么调 |
|---|---|
| 提交新输入 | `invoke(input, config)` |
| 出错后接着跑 | `invoke(None, config)` |
| 回答一次中断 | `invoke(Command(resume=answer), config)` |
| 回到某个节点重放 | `invoke(None, snapshot.config)` |

最常被用错的是第二行。`invoke(None, config)` 的意思是"从最新的 checkpoint 继续"，它只补跑还没干完的活；如果最新 checkpoint 已经没有任何待执行节点，它直接把保存的结果返回，一个节点都不跑。所以别指望用它"再跑一遍"，那是重放，得用第四行，带上历史里的 `snapshot.config`。

```python
# 进程重启后接着跑：输入给 None
graph.invoke(None, config)

# 重放：从历史里挑一份，用它自己的 config
snap = next(s for s in graph.get_state_history(config) if s.metadata["step"] == 1)
graph.invoke(None, snap.config)
```

第三行是 HITL 的正解，`Command(resume=...)` 的值会变成 `interrupt()` 的返回值。具体语义留到第 09 篇。

## 四、pending writes：同一步里成功的不会重跑

这是最值钱的一条细节：checkpoint 除了 super-step 级的快照，还会在 **task 级**记录每个节点完成后的写入。

于是一个 super-step 里三个节点并行，两个成功、一个失败，resume 时框架知道哪两个已经落盘，只重跑失败的那个。不会因为一个节点挂了，把同一步里跑完的活全废掉。

但要注意边界：**失败的那个节点是从函数开头重跑的**。checkpoint 不在节点中间，节点里已经发生的副作用会再来一遍。这就是"节点要幂等"的由来——发消息、扣库存、写库，都得能承受重复执行。

反过来，跨 super-step 的成功节点是绝对不会重跑的，因为整份快照已经提交。所以"最多丢一个节点的进度"，就是这套机制给你的承诺边界；代价是写入表会随任务数增长，节点拆得越碎，行数越多，这也是后面要谈清理的原因。

## 五、durability：三档，按代价选

落盘时机可以调，三种模式：

- `"exit"`：只在执行退出时落（成功、报错或中断）。性能最好，但进程崩了就什么都没有；
- `"async"`：后台异步写，下一步照常跑。兼顾性能与持久，进程崩在写入途中仍可能丢；
- `"sync"`：下一步开始前同步写完。最稳，但每步都要等一次 IO。

```python
graph.stream({"input": "test"}, durability="sync")
```

它还会影响新线程的**第一个** checkpoint：`exit` 模式跑完才落；`sync` 会在第一个用户节点执行之前，先把输入那条和 step 0 提交。有个坑写得很直白——崩溃发生在第一个 checkpoint 落盘之前，这根 thread 和"从未调用过"完全无法区分，`invoke(None, config)` 会抛 `EmptyInputError`。要区分"没接受"和"接受了但丢了"，得自己在 checkpointer 之外记一笔。

怎么选我的经验是：纯可重算的批处理用 `exit`，普通对话和图用 `async`，涉及钱和不可逆动作的节点所在图用 `sync`。三档不是全局设定，按图的性格选就行。

## 六、状态能读也能改

调试和人工修正都靠这三个方法：

```python
snap = graph.get_state(config)              # 最新快照
for s in graph.get_state_history(config):   # 历史，最新在前
    print(s.next, s.metadata["step"])
graph.update_state(config, {"status": "approved"})
```

`next` 是空的就说明跑完了；`metadata` 里有 `source`（input / loop / update）、`writes`（哪个节点写了什么）和 `step`（第几个 super-step）。这几样拼起来，基本能还原"哪一步、谁、写了什么"。

`update_state` 会新建一个 checkpoint，不改旧的，而且和节点更新一样走 reducer——有 reducer 的字段是"累积"，想覆盖得用 `Overwrite`。它还有个 `as_node` 参数，决定这笔更新算谁写的，进而影响下一步从哪个节点继续。这是第 12 篇时间旅行的地基。

顺带说一句：这三招只在"图不是由 Agent Server 托管"时你才需要自己调。用官方 server 的话，持久化是它的事，你只管带上 thread 语义。自建服务才要自己挑 checkpointer、自己接数据库、自己写清理任务。

## 七、存哪，怎么管

- `InMemorySaver` / `MemorySaver` 存在内存里，进程重启全丢，只适合测试和 notebook；
- `SqliteSaver` 落本地文件，开发和小规模够用；
- `PostgresSaver` 上生产：有索引，支持异步，`setup()` 建表。

三个运维细节顺手记下：`PostgresSaver` 的 `thread_id` 列有长度限制，控制在 255 字符以内；checkpoint 会随对话无限增长，得定期清理或设保留策略；子图有独立命名空间（父图是空串，子图是 `节点名:uuid`），父图看不到子图刚写的东西是正常的，别当 bug 查。

## 八、一句话总结

续跑续在 super-step 边界的那份快照上，靠 `thread_id` 找到它，靠 `invoke(None, config)` 接着跑；同一步里成功的写入已在盘上，失败的那个从头再来。

所以真正要设计的不是"怎么续"，而是**每个节点重跑一次会怎样**。想清楚这个，checkpointer 才只是配置项；想不清，它就是一台放大器。
